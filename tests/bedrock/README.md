# Bedrock 統合テスト

PrismarineJS の bedrock-protocol 3.60.1 を使い、実際の Paper / Geyser に接続します。Node.js 24 以上が必要です。

**新しい検証専用ワールドで実行してください。** テストは NativeOH のインベントリ、ゲームモード、位置を変更し、原点周辺に設置用の足場と試験ブロックを作成します。ホワイトリストを無効にします。運用中のサーバーや既存ワールドでは実行しないでください。

## サーバー

検証した組み合わせはリポジトリの README と results の JSON に記載しています。以下は同じ構成を用意する手順です。

1. 新しいディレクトリで Paper を起動し、生成された EULA を確認・承諾します。Paper、Geyser、Minecraft の配布条件に従って各 JAR を別途用意してください。
2. Paper の `plugins/` に対応する Geyser-Spigot を配置します。
3. 本拡張の JAR を `plugins/Geyser-Spigot/extensions/` に配置します。
4. `server.properties` を設定します。

```properties
server-ip=127.0.0.1
server-port=25601
online-mode=false
enable-rcon=true
rcon.port=25602
rcon.password=YOUR_LOCAL_TEST_PASSWORD
difficulty=peaceful
level-type=minecraft:flat
spawn-protection=0
```

5. 生成済みの Geyser 設定へ以下の値を反映します。設定全体をこの抜粋に置き換えないでください。

```yaml
bedrock:
  address: 127.0.0.1
  port: 19195
  transport: raknet
java:
  auth-type: offline
gameplay:
  enable-custom-content: true
  force-resource-packs: true
  enable-integrated-pack: true
advanced:
  java:
    use-direct-connection: false
  bedrock:
    validate-bedrock-login: false
```

これは署名を持たないローカルの自動クライアントを接続するための検証設定です。ループバックに限定し、インターネットへ公開しないでください。

6. Java 26 でサーバーを完全に再起動します。RakNet cookie とネイティブイベントループを無効にした構成で検証しました。

```bash
java -Xms512M -Xmx2G -DGeyser.RakSendCookie=false -DdisableNativeEventLoop=true -jar paper.jar nogui
```

7. リポジトリ直下へ `.integration/` を作り、`.integration/test-settings.json` に次の設定を保存します。このファイルは git で無視されます。

```json
{
  "bedrockPort": 19195,
  "rconPort": 25602,
  "rconPassword": "YOUR_LOCAL_TEST_PASSWORD"
}
```

## 実行

```bash
cd tests/bedrock
npm ci
npm test
```

接続先は 127.0.0.1、Bedrock 1.26.51、言語 ja_JP、プレイヤー名 NativeOH、検証用 XUID 31001 です。`TEST_SETTINGS` で別の設定ファイル、`TEST_RESULT` で結果ファイルを指定できます。既定の出力先は `.integration/results.json`。`TEST_DEBUG=1` で受信情報を表示します。`TEST_LOCALE=en_US` で英語の表示名を検証できます。

テストは通常の ItemStackRequest と Java の装備・個数を確認します。開いている間は UI 定義、閉じると元のバニラ定義・ブロック状態・データ値となり、Bedrock のスタック ID だけが更新されることを検証します。名前付きの石も開く・移動・閉じる各段階で維持します。石と階段を移動したまま閉じて 1 個設置し、再度開いて残りを戻す操作も行います。表示解除と元の OFFHAND 装備パケットが送られることを検証します。

松明、水バケツ、エンダーパール、ポーション、りんごの使用と、メインハンドの設置を優先すること、範囲外・不正な保持定義を拒否することを確認します。食品の独自 PlayAnimation とプレイヤー姿勢プロパティは登録しません。失敗時は終了コード 1 です。

自動クライアントは Bedrock 本体のドラッグ制限や画面描画を実行しません。実機では、新しい RP 0.2.8 を取得して再接続し、石・石レンガ・剣・斧・パン・りんご・松明を通常のインベントリからオフハンドへ移してください。閉じた後の保持位置と向き、設置・消費、開き直して元へ戻す操作を確認してください。右手と三人称も確認してください。

この基準版はバニラの保持表示を確認する段階で、独自の食品アニメーションを含みません。原点周辺のボット検証と、実機プレイヤーの確認場所は分けてください。

通常の持ち物欄について、部分スタックをオフハンドへ移動し、同じアイテムをまとめ、カーソル経由で分割して戻す操作を追加で検証します。入っているブロックを食品や剣と交換し、剣の耐久値・エンチャント・名前が維持されること、閉じて再び開いた後も持ち物欄へ戻せることを検証します。ボットの Java 側の個数も照合します。

実機の合否は通常のインベントリからの直接操作で判断します。ユーザーが許容した小さいブロック表示は操作の失敗理由に含めません。食品の消費処理と左手の表示・モーションは別々に記録します。

0.2.1 は、受信した UI 定義の剣・斧など 13 種類の `hand_equipped` が true、食品・ブロックなど 6 種類が false であることも検証します。実機では左右の道具を動かさずにインベントリを開閉し、持ち方が切り替わらないか確認してください。このパケット検査だけで見た目の一致を判定しません。

0.2.4 は元の HUD へ画像パス・個数・空画像を送り、対応画像が含まれることを確認します。インベントリ用定義の表示中も HUD はバニラの画像を使います。元の live binding のために定期更新します。Java のタイトル・副題・時間・リセットを送っても HUD データを上書きせず、アクションバーが使えることを確認します。元の UI と同じく通常タイトル・副題は非表示です。実機では通常のホットバー・体力・空腹と左端の枠・アイコン・個数を確認してください。

HUD と通常通知の同期だけを短く試す場合は `TEST_HUD_ONLY=1 npm test` を使います。このモードは結果 JSON を書かず、画面描画の検証も行いません。通常の統合テストでは Java 側の装備確認とコンテナの閉じる応答を待ち、食品を使う前に空腹を確認します。

食事の試験では use 入力を保持した状態を模して、150ms ごとに使用パケットを送り、消費中の再入力で Java の使用時間がリセットされないことも確認します。

テスト用プレイヤーだけに耐性を付与し、エンダーパールから出たエンダーマイトの攻撃で検証が中断されないようにします。移動リクエストの成功応答は Geyser の予測結果なので、Java 側の装備・個数の確定も待って検証します。

0.2.5 は、13 種類の移動用道具に種類別の `components.render_offsets` プリセットを設定したことも受信データから検査します。食品・ブロックなど 6 種類へ道具用プリセットを追加しないことも確認します。これは Geyser の内部登録データの確認であり、現行 Bedrock がプリセットを使うか、開閉時の姿勢が一致するかは実機で判定します。

0.2.5 の種類別プリセットは、実機で左手の斧の向きを直せませんでした。0.2.6 はこれを削除し、インベントリが開いている間も左右の装備パケットに元のバニラ定義・ブロック状態・データ値・個数を使うことを 23 種類で検査します。インベントリにある移動用定義と、実際の Java の装備・個数の往復確認も続けます。自動クライアントは装備パケットを描画に適用しないため、実機で左手の斧と右手の剣の開閉を確認してください。

実機参加者の検証鯖では Peaceful・持ち物保持・敵の自然出現停止を設定しています。自動試験は実行前の難易度を記録し、食事を検証するため一時的に Easy に変更し、成功・失敗どちらの場合も終了処理で元へ戻します。通常終了以外の強制停止時には、難易度を確認してください。

0.2.7 は実機で効果がなかったインベントリ表示中のバニラ装備パケット補正を削除します。その補正専用の 2 項目を除いた 68 項目で、移動・保持・設置・消費・HUD を検証します。UI 用の剣・斧・採掘道具 35 種類には左右別の attachable を追加しました。実機では、右手の剣と左手の斧についてインベントリ開閉時の向きと大きさ、開いている間の出し入れを確認してください。Blockbench のモデル確認は実機描画の合格判定には使いません。

0.2.7 は実機で、インベントリ表示中の背景の左手の斧が消える／ずれる結果でした。0.2.8 は負の倍率を使わず、回転と支点で同じ形を表す比較候補です。モデルの表示に関する変更であり、実機での見た目は別に確認します。
