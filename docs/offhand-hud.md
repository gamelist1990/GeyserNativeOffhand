# オフハンド HUD の修正

RP 0.2.3 は自動テストで同期を確認できましたが、ユーザーの実機画像で通常のホットバー・体力・空腹などが消える問題が確認されました。自動クライアントは JSON UI を実行しません。

0.2.3 は独自の nativeoffhand_hud_inject.json から hud.root_panel を登録していました。画面のルート定義を別のファイルで再登録する経路が通常の HUD を破壊した可能性があります。0.2.4 はこれを削除し、ユーザーの指示に従って元ファイルを取り込みます。

## 0.2.4 で原本と一致したファイル

DoubleHands 5.6.0 の作者表記は Areed Elahi。次のファイルは内容を変更せずコピーしています。

- ui/_ui_defs.json
- ui/hud_screen.json
- ui/doublehands_hud.json
- textures/ui/offhand_slot.png と textures/ui/empty.png
- textures/items/iso_renders/*.png の 1,674 枚

元の ui/hud_screen.json の modifications で HUD へ枠を追加します。元の image コントロールと画像を使い、前版の inventory_item_renderer と保存用 binding は含めません。

## Geyser 側の同期

元の TextureMap を、名前を minecraft: なしに揃えた properties に変換します。まずバニラの Bedrock の定義から名前を取得し、移動用 alias は使いません。Java 名での参照と元と同じ textures/items/<name> のフォールバックも用意します。

title は画像パス、subtitle は 2 個以上なら個数、1 個なら空文字。空なら textures/ui/empty を送ります。表示時間は 2 秒、装備・個数の変更時と、変化がない場合は 1 秒ごとに更新します。250ms ごとに状態を確認し、切断時にタスクを解除します。

元の DoubleHands UI は通常のタイトルと副題を隠します。この版ではそのチャンネルを専用に予約し、Java の title/subtitle/times/reset を受けても HUD を更新します。アクションバーは元の translator へ渡します。通常タイトルの表示との共存機能はこの版にはありません。

インベントリ移動・設置・Java 側の食事処理と、遅延インベントリ処理は維持します。元の Script API や行動パックは Geyser で実行しません。

## 実機確認

RP 0.2.4 を取得し、通常のホットバー・体力・空腹表示と、その左の枠・アイコン・個数を確認します。石・パン・斧の移動、消費による残数の更新、1 個で数字が消えること、空で枠が消えること、タッチボタンに重ならないことも確認します。

自動テストは Java の装備・消費・パケットと画像ファイルの存在を確認します。実機描画の合否には使いません。UI・画像の原本とのハッシュ一致も記録します。

0.2.4 の実機確認では、ユーザーから HUD が良好との報告を受けました。残っている斧・道具の開閉時の向きの問題は HUD とは別に記録します。0.2.5 は UI・枠・画像を変更せず、移動用の道具の登録データだけを補います。

## 0.2.14: アイコン画像の全削除

ユーザーが画像群の全削除と枠画像の維持を指示したため、`iso_renders` の 1,674 PNG、未使用になる `textures/ui/empty.png`、旧 `offhand-hud-textures.properties` を削除しました。パックの PNG は `textures/ui/offhand_slot.png` だけです。

`ui/_ui_defs.json`、`ui/hud_screen.json`、枠 PNG は前版と同じ内容です。元のルートへの追加方法を保ち、`doublehands_hud.offhand_slot_content` の画像コントロールだけを custom `inventory_item_renderer` に替えます。枠・個数・タッチ／クラシック配置を維持します。

title の形式は `(native runtime ID << 16) | (native data value & 0xffff)` の符号付き整数の文字列表現です。UI では `(#nativeoffhand_aux_string / 1)` を `#item_id_aux` に渡します。空は文字列 `0`、1 個以下の subtitle は空です。ネイティブの ID は Geyser のインベントリ alias 用の変換範囲の外で取得します。

パックは 50,834 バイトです。同期試験では実際に受信した item registry・保持アイテム・データ値と AUX を照合します。石、パン、赤い羊毛、りんご、斧、1 個、空、定期更新、通常通知との干渉、インベントリ用 alias の表示中も元の AUX が送られることを検証します。自動クライアントは JSON UI の数値変換とアイコン描画を実行しません。

RP 0.2.14 を取得して入り直し、通常のホットバー・体力・空腹が見えることと、左の枠に石・パン・斧などのアイコンと正しい個数が出ることを実機で確認します。空では枠が隠れ、インベントリを開閉しても出し入れできることを確認します。色・模様・ポーション・エンチャントなど、AUX だけでは表せないスタックの表示は別途確認が必要です。

## 0.2.14 の実機結果と 0.2.15 の診断

ユーザーの実機では「枠は出るが、アイコンは何も表示されない」と確認されました。0.2.14 は描画の失敗です。70 項目のパケット試験と画像の全削除・容量削減の確認は、JSON UI の renderer 成功を保証しません。

0.2.15 は文字列の数値変換を `(0 + #nativeoffhand_aux_string)` に替え、比較用に A/B/C を並べます。A は公式 UI と同じ固定値 3801088 の作業台、B は変換したオフハンド AUX、C は `hotbar_items` の 1 番目から `common.item_renderer` へ実際の `#item_renderer_data` を渡すコントロールです。左上の受信値表示も含め、RP 更新・固定 renderer・数値経路・ネイティブ collection を一度の実機確認で分けます。診断用で、本番への導入や成功の判定には使いません。

変換の参考: [Bedrock Wiki の現行バージョンに関する注記](https://wiki.bedrock.dev/json-ui/type-conversion#string-to-number)。これは実機結果の代わりにはなりません。

## 0.2.16: 標準 HUD の描画構成への変更

実機画像の D15 AUX 65536 と A/B/C の文字から、診断 UI は読み込まれ、左手の石の AUX が届いていることを確認しました。固定値 A、数値変換 B、collection C の全てのアイコンが非表示でした。

0.2.16 は画像式 UI の親 layer 100 と診断行 layer 110 を両方 1 へ下げ、アイコンを layer 3 へ揃えます。標準 hud.hotbar_hud_item_icon と同じ force_update: true を設定し、C もその標準コントロールを直接参照します。A/B/C と D16 の受信値表示で、変更後の実機描画を確認します。レイヤーと更新設定を同時に変えた候補なので、結果が改善しても片方だけが原因だったとは断定しません。保持位置やアイテム移動のコードは変更しません。

## 0.2.16 の実機成功と 0.2.17 の整理

ユーザーから「全部見えた Bがオフハンドのやつ」と報告されました。石の OFFHAND アイコン、固定作業台、数値変換したオフハンド、ネイティブ hotbar の描画が実機で表示されました。成功した変更は、標準 HUD に合わせた低い layer と force_update 設定です。両方を同時に変更したため、原因を片方だけに断定しません。

0.2.17 はこの設定を維持して A/B/C・D16 の診断コントロールを削除します。オフハンド枠と個数だけの通常 HUD に戻し、1,674 アイコン PNG と旧 Properties は削除したままです。最終パックは 50,847 バイト、同梱 PNG は枠 1 枚です。保持用の ID、インベントリの移動、道具のモデルと姿勢はこの整理で変更しません。

最終版ではパン・斧等への切り替え、個数、1 個・空状態、インベントリ開閉を確認します。石以外の特殊なスタック表示や他のカスタムパックへの追従は未確認です。


## 0.2.18 の撤回と標準 renderer の比較

画像パス方式の0.2.18は欠落テクスチャの報告で取り下げ、0.2.17へ戻しました。0.2.19は標準AUX方式で符号変換とdata-drivenのローカル番号を補正しましたが、ランタン・魂の松明は実機で非表示でした。0.2.20は同じrendererへ固定値・2通りのカスタム番号・完全なスタックのcollectionを渡す診断版です。[経緯と現在の確認事項](native-hud-aux-repair.md)。画像PNGは枠1枚の構成を維持しています。


0.2.20の実機でAに魂の松明が表示されると確認されました。0.2.21は同じ整数AUXの標準rendererを枠内へ移し、Mojang mainの携帯用定義とGeyserのIDから65種類の固定AUXを生成します。比較表示を削除し、PNGは枠1枚を維持します。最終パックは53,056バイトです。枠内での最終表示と他の種類の描画は確認待ちです。

## 0.2.21の実機結果と0.2.22のA/B併用

0.2.21の実機ではランタン類・魂の松明の枠内アイコンが正常、りんごは非表示と確認されました。0.2.22はAの固定整数AUXを維持し、Bを元の `(0 + #nativeoffhand_aux_string)` と補正前のネイティブIDへ戻します。Aに一致する時だけBを隠し、同じ枠に1つのアイコンを表示します。りんごの同期・インベントリ往復を重点試験に含め、実機描画は別に確認します。[詳細](native-hud-aux-repair.md)。

0.2.22の実機でもB系が非表示だったため、0.2.23はGeyser側でA/Bを選びます。Bの接頭辞だけで表示を切り替え、Bの場合はAの親パネル全体を隠します。Aの成功した入力は維持します。[0.2.23の詳細](native-hud-aux-repair.md)。
