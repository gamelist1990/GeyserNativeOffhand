# カーソルと同種スタックの一時定義・軽量化

0.2.28では、通常のインベントリと左右の保持アイテムをバニラ定義のまま送ります。持ち物欄で掴んだカーソルと、同じ種類の結合先だけ、`allow_off_hand` を持つ移動用定義へ変換します。オフハンドへ置いた後は元のバニラ定義へ戻し、オフハンドから掴んで戻す操作にもバニラ定義を使います。

## 同期

`NativeInventoryView` はカーソルの移動元を記録し、take/place/swapの処理後に触ったスロットを再通知します。StackResponseにはアイテム定義が含まれないため、この通知でクライアントの予測したカスタム定義を元に戻します。個数、名前、耐久値、NBT、ネットワークスタックIDはGeyserが管理します。

`NativeHeldView` は送信経路を委譲し、同一内容のインベントリ全体・オフハンド装備の再送を省きます。掴んでいる間だけ同じ種類のスロットを一時定義に揃えます。装備パケットはネイティブ定義を維持します。スロットの実際の移動は再送抑制の対象にせず、オフハンドの移動後にはキャッシュを無効化して補正を送ります。画面を開閉するだけでAIRや別の保持定義を挟む処理はありません。

この送信ラッパーはGeyser内部APIへ依存します。接続終了・拡張終了時に元の送信経路へ戻します。将来のGeyser更新時は再検証が必要です。

## 軽量化

左手食事アニメーション、同期プロパティ、食品専用モデル、道具のUI保持モデルを削除しました。パックには食事コントローラー、attachable、モデル、アニメーションを含めません。アイテム画像はバニラの既存資産を参照し、PNGはオフハンド枠1枚だけです。RP0.2.28の圧縮サイズは9,733バイトです。

右手のアニメーションやプレイヤーの描画定義を上書きしません。剣でチェストを開く操作は、非スニーク時の操作対象ブロックを確認してGeyserの通常処理へ渡します。

自動試験はパケットとJavaサーバーの状態を検証します。実機でのドラッグ可否や開閉時のちらつき解消を保証する描画試験ではありません。別途、ユーザーによる石・斧・パンの実機確認で移動と一瞬の消失解消が報告されています。

## 0.2.29: レッドストーンのカーソル表示

レッドストーンにはJava側のブロック配置情報もあるため、ブロック配置モデルだけを定義すると掴んだ時に配線の形になります。カーソル定義では既存の粉アイコンを優先します。毎回のビルドでMojangの同一mainコミットの `textures/item_texture.json` を確認し、`redstone_dust` の画像パスを生成します。PNGのダウンロード・同梱はありません。Java側の設置動作や保持定義は変えません。ほかのアイコン差分を自動ですべて修正する仕組みではありません。

## 0.2.30: 同じスタックへの結合

カーソルだけをカスタム定義にすると、通常スロットにある同じアイテムとBedrockの定義が異なり、実機UIが結合操作を拒否しました。掴んでいる間はプレイヤーの持ち物欄・ホットバー・オフハンドの同じJavaアイテム種類を揃え、カーソルが空になったら元の定義へ戻します。違う種類は変換しません。戻す方向でオフハンドから掴んだ場合はカーソルもバニラのままです。

描画のための装備パケットはバニラのまま維持し、右手用のカスタムモデルや食事アニメーションは追加しません。ネットワークスタックID、個数、NBTは保持します。名前や耐久値などが違う、バニラでも結合できないスタックを強制結合する変更ではありません。

自動クライアントには、既存スタックへplaceする前にアイテム定義が同じことを要求する検証を加えました。これにより実機が拒否する異なる定義同士の結合を、パケットだけで迂回して合格扱いすることを防ぎます。部分スタックを通常スロットとオフハンドへ結合し、置いた後に両方がバニラへ戻ることを確認しています。別コンテナの結合操作は今回の試験対象ではありません。

## 0.2.33: タッチ操作での直接移動

タッチ操作／Pocket UIは、スロット選択がクライアント内で完結してカーソル要求を送らない場合があります。カーソルだけの変換では移動元に `allow_off_hand` がないため、オフハンドへのタップが拒否されます。プレイヤーの持ち物画面を実際に開く直前に、持ち物欄・ホットバー・オフハンドを移動用定義へ揃えます。閉じる際や別のコンテナを開く際に復帰し、装備パケットにはネイティブ定義を使います。

入力モードはGeyserの現在の入力情報を優先し、未確定時のみログイン情報を参照します。Pocket UIは入力機器にかかわらず対応します。PCのカーソル処理は従来のままです。自動試験はタッチプロフィールの直接移動、結合・交換、カーソル未使用、スタックID保持、閉じた後の復帰を確認します。実際のiPad画面でのタップ可否は確認待ちです。
