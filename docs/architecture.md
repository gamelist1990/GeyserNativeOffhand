# 実装の構成

## インベントリと保持アイテム

`NativeItemCatalog`はGeyserのアイテムマッピングとブロックパレットから、通常のインベントリで移動できる定義を生成します。検証した環境では1,625件の `nativeoffhand_ui:` 定義を登録しています。

`NativeInventoryView`はプレイヤーインベントリを開いている間だけ移動用の定義を選び、通常のItemStackRequestをGeyserへ渡します。部分スタックの移動、結合、カーソルによる分割、既存のオフハンドとの交換も同じ経路を使います。

閉じると元のバニラIDとブロック状態へ戻し、両手の表示を更新します。表示用の定義が変わる場合はBedrockのスタックIDを更新し、Java側の種類・個数・名前・コンポーネントを維持します。遅延して開くインベントリもセッションのイベントループ内で処理します。

NONE・LEGACYの保持定義は元の内容を使います。元からdata-drivenの定義にはオフハンド許可を設定します。無効化時にはtranslator、変更した定義、翻訳を復元します。

## インベントリ表示中の道具

移動用の剣・斧・採掘道具35種類に左右の手を判定するattachableを登録しています。左手・一人称はバニラの盾の保持構成を基準とし、クライアントの元のテクスチャを使う立方体で形を描きます。

左手の向き・倍率・ピクセル厚みはBlockbenchのバニラJava左手モデルと比較し、位置は通常画面とインベントリ背景の画像から調整しました。[モデルと確認の記録](ui-tool-attachables.md)。プレイヤーのモデル・ボーンやゲーム画面のバニラ保持モデルを置き換える処理はありません。

## 設置・使用

`NativeUseRouter`は右手で使用できるアイテムを優先します。右手が空、または剣などの使用しないアイテムの場合に、オフハンドの使用をJavaへ送ります。対象外の操作は元のGeyser translatorへ渡します。

ブロック設置ではGeyserの到達距離判定、保持定義、カーソル、ワールド境界、連続入力、予測の状態を確認します。食品・ポーションの消費はJava側で処理し、消費中の繰り返し入力で使用時間をリセットしません。JavaのすべてのPASS判定を再現したものではありません。

## オフハンドHUD

DoubleHands由来のHUD登録・枠・個数・タッチ／クラシック配置を使い、アイコンをBedrock標準の `inventory_item_renderer` で描きます。移動用の定義へ変換する範囲の外で、保持スタックのネイティブIDとデータ値を取得します。

AUXは `(native runtime ID << 16) | (native data value & 0xffff)` の符号付き整数です。ビルドで生成する65種類のAUXに一致した場合はA、ほかのスタックはBを選びます。

| 経路 | titleの内容 | 描画 |
| --- | --- | --- |
| A | ネイティブAUXの数値文字列 | 同じAUXを整数property_bagに持つcontrolを選択 |
| B | `B`とネイティブAUXの数値文字列 | 接頭辞を除いて数値化し、動的rendererへ渡す |
| 空 | `0` | 枠を隠す |

Bを選ぶ時はAの親パネル全体を非表示にします。アイコンはlayer3、個数はlayer4です。subtitleは2個以上なら個数、1個以下なら空文字です。250msごとに確認し、変更がなくても1秒ごとに更新します。切断時はタスクを解除します。

通常タイトル・副題のチャンネルをHUD専用に予約し、サーバーのtitle/resetで表示データが上書きされないようにします。アクションバーは元のtranslatorへ渡します。[A/B経路の修正記録](native-hud-aux-repair.md)。

パックは枠PNG1枚、インベントリ用の道具のモデル・保持アニメーション、UIとバニラ画像パスへの参照を含みます。1,674枚のアイコンPNGと旧TextureMapは削除しました。Mojang mainの確認と数値生成は[ビルド時](building.md)に行います。
